What this agent does

It runs the verification lifecycle of an FPGA synthesis tool end to end: it plans tests from a feature spec, runs a regression of designs across synthesis flows, proves every netlist against its RTL with SAT-based equivalence, groups failures into clusters, shrinks them to minimal reproducers, drafts defect reports for a human to approve, and re-runs the fixed build to close them. Then it measures its own triage accuracy on labelled data.

The tool under test is Yosys (synth and synth_xilinx for AMD/Xilinx 7-series), used as an open-source analogue of a commercial synthesis tool. A thin shim injects realistic, option-triggered tool defects so there are real bugs to find. Nothing here uses or claims anything about Vivado or Vitis.

How it can be used

On top of a nightly regression for a synthesis or compiler tool, to cut triage time: many failures become a few clusters, tool bugs are separated from test bugs and infrastructure faults, developers get a minimal reproducer and a ready-to-approve defect report, and fixes are verified automatically.

The same steps are exposed as MCP tools (run_regression, triage, get_coverage, draft_defect) so an AI assistant can run them on request.

Design rules

Deterministic oracles decide pass or fail, never the LLM. Every model output is schema-validated with a rules fallback. Nothing with impact is filed without human approval. The agent's own accuracy is measured on labelled data and reported, including where the LLM is worse than the rules.

This site shows the recorded run and lets you run single jobs live; the full 65-job pipeline runs from the command line (python -m vagent demo).

Run a regression job in your browser

Pick a design, a synthesis flow and a build. Yosys runs locally as WebAssembly, then the same checks the agent uses decide pass or fail. Nothing is uploaded.

The first run downloads Yosys (about 25 MB, cached by your browser). A job takes 10 to 40 seconds: synthesis, then a SAT proof against the RTL.

Triage: 27 failures in 10 clusters

Failures are normalised into signatures and clustered, compared across flows, re-run if they look like infrastructure, matched against known defects and classified. Tool defects are shrunk to a minimal reproducer.

Defects, approval and fix verification

Drafts are filed only after a person approves them (vagent approve --by NAME). Fix verification re-runs the reproducer and the affected jobs on the fixed build.
